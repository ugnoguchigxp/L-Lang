## 1．論文の到達点

自然言語要求と入力契約からLLMが生成したIRを検査・保存し、Wasm実行へ接続する方式の設計・実装と実現可能性を示す。採用済みIR・契約・ビルド条件から同一のWasmを再構築できることを、別の評価軸として示す。

人間の理解容易性、速度優位、一般的な攻撃耐性、広いモデル比較は今回の中心主張に含めない。上位LLMが要求自体を生成する経路は、現時点の証拠に含まれない。新たに含める場合は独立した評価を追加する。

「十分」の判断は採択保証ではなく、本文の各主張に対象・方法・結果・限界・再現手順が対応していることを基準にする。成功率の目標を後付けして達成するのではなく、失敗や成立しない範囲も結果として残す。

## 4．推奨する作業順序

1. **証跡の保全（E01・E02）**：まず元の記録を保全する。元live応答をfixtureへ書き換えて由来を失わせない。
2. **実装と主張の対応（E03・E04・E06）**：既存コードとtestを調べ、論文に必要な説明・拒否事例を整える。
3. **独立した正解と再構築（E05・E07）**：現在の1課題について根拠を完結させる。
4. **関連研究（E09）**：主張が既存技術とどう異なるかを整理し、必要なら題名・貢献文を修正する。
5. **成立範囲の拡充（E08）**：準備済みの評価条件に従って追加課題を評価する。
6. **配布と本文反映（E10・E11）**：再現手順と集計を固め、本文の数値・限界を更新する。

E12・E13は本文の主張を広げる判断をした場合だけ着手する。初期の根拠充足では人間参加実験、性能最適化、Effectsの攻撃比較を追加しない。

## 5．追加評価で保存する最小単位

| 区分 | 保存する情報 |
| --- | --- |
| 識別 | task ID、trial ID、実行日時、対象commit、入力hash |
| 要求 | 自然言語要求、型契約、対象profile、作成・reviewの由来 |
| 生成条件 | 正確な指示・schema・入力、モデル指定、provider、設定、予算、修正上限 |
| 応答 | 各回の応答、usage、停止理由、未解決・エラーも含む全試行 |
| 採用 | IR、Lock、手修正の有無と差分、採用・拒否理由 |
| コンパイル | 契約、compiler/backend、依存lock、設定、Wasm、manifest |
| 正解・実行 | 独立Oracle、source例、生成suiteを分けた結果、host条件、不正入力結果 |
| 再現 | 再ビルド環境、API呼出し0の記録、hashとbyte比較、再実行コマンド |

初回成功、修正後成功、人間による修正後成功は別に数える。失敗を削除せず、parse、型・制約検査、コンパイル、実行、期待値不一致、運用失敗を区別する。過去の事例は探索的事例として扱い、後から新しい評価の未観測データとして扱わない。

## 6．既存事例をオフラインで確認するコマンド

以下は既存の`artifacts/codex-terra/access-live`が存在するローカル環境用である。配布用の完全な再現手順ではない。出力先は毎回未作成のディレクトリ名にする。依存導入済み・リポジトリ指定のBunを前提とする。

```sh
bun run capability replay-development artifacts/codex-terra/access-live --out-dir artifacts/paper-replay-new
bun run prompt build artifacts/codex-terra/access-live/attempt-0/source.json --out-dir artifacts/paper-build-a-new
bun run prompt build artifacts/codex-terra/access-live/attempt-0/source.json --out-dir artifacts/paper-build-b-new
bun run examples:matrix artifacts/paper-matrix-new
```

期待結果は、replayの`status: pass`、`replay-check.json`の`match: true`と`apiCalls: 0`、実行検証10件pass、過去成果物と各buildのWasm bytes一致、およびmatrixの全4経路成功である。

失敗した場合は出力・終了値を保存し、元証跡を変更せずに、入力差、依存差、コード差、実行条件差を調査する。失敗後の修正版による成功は別runとして記録し、最初の失敗を上書きしない。Wasmのhash比較だけでなくbyte比較を行う。パッケージhashとWasm hashを混同しない。

## 7．評価開始の境界

既存証跡の読取り、文書化、オフライン再生と再ビルドは、追加live評価と分けて進められる。新しい実モデル評価、独立datasetの確定、人間参加者を伴う評価は[研究評価の実行条件](../RESEARCH_EVALUATION_PREREQUISITES.md)に従い、条件と必要な承認を整えてから実施する。本一覧の作成を実行承認とは扱わない。
