## JSON Semantic IRを正本とする再実装

同日、ユーザーの指摘により構成を作り直しました。旧版のTS形式のゲーム実装とブラウザ側の履歴管理は、JSON IRを正本にして極力Wasmで実行する意図を満たしていませんでした。

現在の正本は`reversi.semantic.llang.jsonc`です。自然言語の要求を`semantic-request.json`に保存し、親エージェントが型付きcollection JSON IRを直接構成しました。IRにはルール・AIに加え、初期化・手番・対局状態・人間手の履歴・Undo・自動進行の指示・表示モデル・状態文を定義しています。旧Predicate IRではゲームを表現できないため、既存の`module-collection-v1`を使用しています。名前だけをSemantic IRに変えたTS実装ではなく、保存したJSONが実際のコンパイル入力です。

`game.ts`・`controller.ts`・`client.ts`を削除し、ビルド対象をWasmだけに固定しました。`bridge.js`はDOM表示・イベントの転送・Wasmから指示された操作のタイマー実行、`wasm-runtime.js`は汎用ABIの入出力だけです。対局の処理はブラウザ内のWasmで行い、サーバーは静的配信のみです。要求とIRの保存は実装・検証の境界であり、自然言語の要求が自動で完全に証明されたという主張はしていません。

`dist/`のIRコピー、manifest、Wasm、画面用ファイルはGit管理対象として残す構成にしました。manifestの入力はJSON IRだけ、ビルド対象は`wasm`だけです。IRコピーのhashとmanifestのsource hash、Wasmのhashを検証して起動します。

47テスト・3,002 assertionsを通過しました。独立ルールとの3対局、ブラウザ用ABI接続と標準ランタイムの出力一致、Wasmが管理する履歴・Undo・パス・表示、ブラウザ接続を用いた3対局の終局、成果物とIRの破損検出を含みます。ブラウザで着手・AI応答・Undo・着手直後の再開始を確認し、error/warnログは0件でした。前版の対局API・非同期controllerに関するテストは現構成の静的配信とWasm状態遷移のテストへ置き換えています。

追加のLuna SDK呼び出しはありません。この再実装の親エージェントのトークンはSDK記録に含まれず、全体のトークン量を取得できていません。元のSDK消費量を再実装の消費量として扱いません。旧版のスナップショットはローカルの`artifacts/reversi-rebuild/previous/`に保存しました。今回のcontext_compile / compile_evalは各1回です。
