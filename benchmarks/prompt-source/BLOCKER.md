# 実モデル評価へ進むために不足している条件

> 適用範囲の訂正（2026-09-15）：以下は研究評価・有料実行の条件を整理した記録であり、開発全体のブロッカーではない。人間の都度レビューを運用の必須工程にはしない。今後は[エージェント能力拡張コンセプト](../../docs/AGENT_CAPABILITY_IMPLEMENTATION_CONCEPT.md)に従い、Coding Agentの部品検証とSAAAの受け入れ検証を実装する。live評価モードの接続や予算制御の実装も先行できる。人間A/Bの準備は、小規模な機能検証には不要。

2026-09-15。実装・fixtureによる動作確認を進めた後の外部条件。

[Research evaluation prerequisites](../../RESEARCH_EVALUATION_PREREQUISITES.md)には「API費用が発生する実行、人間参加者の調整、独立datasetの確定は、このリポジトリのコード変更とは別の明示的な承認を必要とする」とある。今回の実装継続の指示から、モデル・費用上限・独立レビュー担当者を推測して確定はしていない。

不足しているもの：

1. **独立レビューとdataset確定**：現在の4課題は実装者が作ったdraft。要求変更の意味、未解決とすべき条件、期待結果を別の担当者が確認し、評価対象・反復数・閾値とhashを結果を見る前に確定する。
2. **live実行条件**：provider/model、token・費用・wall-clock上限、実行承認。認証情報の存在だけで承認とは扱わない。
3. **人間A/Bの条件**：総作業時間を比較する場合は参加者、domain owner、同意・データ取扱い、同一課題、手書きbaseline、計測方法、停止権限を確定する。

現時点のrunnerはfixture検証専用。上記確定後に、その予算・停止条件を適用するlive実行モードを接続する。実モデルの正解率、作業時間の短縮率、費用対効果はまだ報告できない。

このblockerをmemory profileや別backendの実装で迂回しない。現在のprofileで表現できない実利用上の処理が確認されれば、その具体的な要求をもとに段階Eを計画する。
